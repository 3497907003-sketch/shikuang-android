# Independent 16KB WebView control experiment

This is a separate diagnostic APK (`com.shikuang.control16k`) and separate instrumentation APK. It is not included in `android/settings.gradle`, does not add an Activity to the product manifest, and contains no Capacitor, mineral engine, product assets, model, credentials or release tasks. Its only Activity is not exported and has no launcher intent. The manifest has network-state permission, but no internet permission.

The control uses the official device WebView provider, a local HTML string with three inputs, native touch, a genuinely visible system IME, and native `InputConnection.setComposingText`. Its 12 bounded launch/background/foreground/recreate/close cycles comprise 3 no-edit cycles and 9 edited cycles. A localStorage sentinel is verified across lifecycle changes; this does not test the product's IndexedDB implementation. Every edited cycle composes Chinese text before background, recreate and close, with strict DOM equality. Keyboard suggestion selection is not claimed.

The control removes its WebView from its parent and destroys it once in Activity.onDestroy. The product retains its unmodified Capacitor lifecycle, which destroys in onDetachedFromWindow. These are documented comparison conditions, not a production fix. Internal phase checkpoints and genuine focus/window/IME screenshots distinguish which actual operations complete. Native connection evidence is collected before composition; the same current connection is used, never a stale connection after destruction.

CI builds the control and its tests before boot, then runs this control once followed by the original product protocol once on the same official API35 x86_64 image. Both hard-assert actual 16384 page size and no native active network. Failed control steps do not suppress the original-app experiment. All logs, exit-info, tombstones, phase JSON and actual screenshots are retained; the comparison job passes only when both complete all 12 cycles and 9 real input cycles. Neither a pass nor a provider version comparison closes the historic crash root cause.

Run only through the authorized workflow `lifecycle_comparison` input. No automatic repeat, merge or release is performed.
